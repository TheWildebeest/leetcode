## problem

You are given an integer array nums sorted in non-decreasing order, remove some duplicates in-place such that each unique element appears at most twice. The relative order of the elements should be kept the same.

## tl;dr

remove numbers from an array if they appear more than twice.

sounds simple

## \<think\>

just loop through, when we find dupes, nuke them.

is it harder than that?


## attempt 1

```ts
function removeDuplicates(nums: number[]): number {
    const LENGTH: number = nums.length;
    let count: number = 1;
    let spliced = 0;

    for (let i = 0; i < nums.length; i++) {
        // Track # of times we've seen this number
        if (nums[i] === nums[i - 1]) {
            count++;
        } else {
            // Reset counter
            count = 1;
        }
        if (count === 3) {
            // Keep deleting the number at the current index
            // if it's still the same as the previous number
            // This should execute at least once.
            while (nums[i] === nums[i - 1]) {
                let tmp = nums[i];
                nums.splice(i, 1);
                nums[LENGTH] = tmp;
                spliced++;
            }
            // Reset i so we continue the loop from the same index
            // which has a new number now
            i--;
            count = 1;
        }
    }
    return LENGTH - spliced;
};
```

### result

it passed all the test cases.

but it exceeded the time limit!

what am i doing wrong?


## \<think\> again

any time i use a loop within loop something goes wrong.

especially with my while loops and splicing arrays.

thinking about it — splicing means the rest of the array needs to be re-ordered.

its just the javascript hides that implementation detail.

so i can make it faster by:

- storing "current number" as well as "count"
- when count is above 2, replace the number at `nums[i]` with a placeholder or null or something.
- this means I can just loop through in linear `O(n)` time.
- then at the end, sort the array so all the junk goes to the end.

## attempt 2

```ts
function removeDuplicates(nums: number[]): number {
    const NAN = Number.POSITIVE_INFINITY;
    const LENGTH: number = nums.length;
    let count: number = 1;
    let currentNumber = NAN;
    let spliced = 0;

    for (let i = 0; i < nums.length; i++) {
        if (nums[i] === currentNumber) {
            count++;
        }
        if (nums[i] !== currentNumber) {
            count = 1;
            currentNumber = nums[i]
        }
        if (count > 2) {
            nums[i] = NAN;
            spliced += 1;
        }
    }
    nums.sort((a, b) => a - b);
    return LENGTH - spliced;
};
```

### result

it passed! 

runtime - 56ms — not great, but it beats `73.36%` of submissions so i am happy with that

### my takeaways

i seem to overcomplicate every problem i come across.

i want to do something clever like "looking ahead", to be efficient

but it just makes it horribly inefficient.

part of the subsceptibility is because of things like

- `Array.prototype.splice()`
- `Array.prototype.sort()`

which have hidden implementation details, but have a big impact on the time complexity.

need to remember this for my next problem!
